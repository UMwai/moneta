# ADR 0005 — Secrets at rest

**Status:** accepted

## Options

1. **AES-256-GCM envelope encryption of provider tokens/keys with a server-side
   `APP_ENCRYPTION_KEY` env var** — simple, standard, keys never leave the host.
2. Plaintext in DB, rely on disk encryption — unacceptable: DB file gets copied around
   for backups.
3. OS keychain / KMS integration — great in cloud, unavailable/overkill for a generic
   Docker self-host target.

## Decision

**Option 1.** `src/lib/crypto.ts` exposes `seal()/open()`; every provider access token,
client secret, and API key passes through it. `APP_ENCRYPTION_KEY` is generated by the
first-run wizard if absent and documented in `.env.example`.
